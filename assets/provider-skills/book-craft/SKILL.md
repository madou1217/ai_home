# book-craft — 工业级技术专著全流程创作与一键出书专家

`book-craft` 是专为**任何开源软件、底层框架、分布式系统、AI 运行时与工程工具**量身定制的【大师级/源码剖析级技术专著创作专家】。

## 📚 二、高密度、穿透式写作标准（拒绝干瘪，必须透彻）

编写具体章节时，**每一个机制必须配有真实的源码调用与可执行示例**，杜绝任何假大空的空话套话：

### 深入案例对比标准：以“调度与子代理协同”为例

❌ **低质量/干瘪写法（严厉禁止）**：
> “系统支持 `/loop` 命令进行定时任务，还支持 subagent 进行并发处理，通过消息总线通信，提高了执行效率。”

✅ **book-craft 大师级深度写法（标准范式）**：
> 1. **设计动机与第一性原理**：为什么有了 Cron 还要设计 `/loop`？解析固定间隔轮询与自适应动态唤醒（Dynamic Pacing & `ScheduleWakeup`）的本质差异；
> 2. **Stop Hook 与拦截器机制**：解构会话级 Stop Hook 如何在每轮执行后校验终止条件，防止无限循环跑飞；
> 3. **Subagent 物理生命周期与隔离模型**：
>    - **Fork 模式**：继承父会话全量上下文与内存，共享模型配置，在独立工作线程中运行；
>    - **Isolated Subagent 模式**：基于纯净 Prompt 启动，分配独立的 Git Worktree 沙箱（`wt-*`），文件修改物理隔离；
> 4. **进程间通信与寻址协议**：解构 `SendMessage({to, message})` 与 `ListAgents` 的底层 JSON 载荷与 CAS 锁；
> 5. **完整可复现 TypeScript/Go 源码示例与时序 Trace**。

## 🛡️ 四、代码库资产安全：书籍内容与大图严格不入 Git

- **Git 托管范围**：仅限书籍索引元数据（`README.md`）、阅读器外壳与 WebUI 注册路由；
- **Git 忽略范围**：所有生成的 Markdown 章节（`/docs/*-book/**`）与高分辨率 8K 大图（`assets/images/*.jpg`）全部由本地守护进程离线托管与实时渲染，绝不污染主代码库体积。

## 🚀 五、一键出书标准操作流程 (Playbook)

### 步骤 1：立项与全景深读
```bash
/book-craft scout https://github.com/earendil-works/pi
```
- 自动分析该仓库的 monorepo 结构（`pi-ai`、`pi-agent-core`、`pi-coding-agent`、`pi-tui`）；
- 输出 3 个不同维度的立项建议供用户挑选。

### 步骤 2：用户交互选择与 Prompt 补充
- 用户选择方案并补充重点关注点（如：“重点剖析 pi-tui 的差异化屏幕刷新与微虚拟机沙箱”）。

### 步骤 3：/loop 自动化出书与生图
```bash
/loop 15m /book-craft continue docs/pi-coding-book/README.md
```
- 自动生成专属 8K 概念立体书封；
- 逐章撰写高密度、带源码与真实调用的核心章节；
- 编译生成带 AI 伴读 Copilot 的专属单页 Web 阅读器。

# 账号出口 × 上游地区策略（设计定稿，2026-10-19）

一句话：**出口按账号配**（防风控，每个账号都能独立设置），**地区规则按上游配**（同一上游的所有账号共用一份），
**节点能不能用由「规则 > 实测 > 提示」三层得出**，当前网络落在被禁地区时 **fail-closed 并引导用户设置出口**。

## 0. 现状事实（代码取证）

| 面 | 是否消费账号出口绑定 | 实现位置 |
|---|---|---|
| 网关（Node 承接的请求） | 是 | `resolveAccountEgressRequestOptions`（upstream-endpoints-attempt、codex-adapter、图片、token 刷新、额度探测、模型发现） |
| CLI 启动 | 是（注入 `HTTP(S)_PROXY / ALL_PROXY`，zcode 写原生 setting.json） | `provider-runtime-env.js` → `applyAccountEgressProxyEnv` |
| 桌面端启动 | 是（同上注入 + zcode 原生设置 + 运行中自动重启） | `account-app-launcher.js`、`zcode-egress-service.js` |
| VS Code 类扩展 | **否** | — |
| **Go Core 承接的推理请求** | **否（缺口）** | Go 侧无出口概念；`go-core-route-deferral.js` 也不看出口绑定 |

未绑定时的默认行为：网关请求走 server 全局代理（`aih server config` 的 proxyUrl），CLI / 桌面端继承启动环境。

**P0 缺口**：当前 `gateway.anthropic.messages / openai.* / gemini.*` 等推理入口已交给 Go。账号一旦绑定了
url / pool / system 出口，而请求被 Go 承接，就会**绕过账号出口直连**。修复：出口绑定为非直连的账号，
请求交还 Node（与 `account_error_rules` 同一套「钉选看自己 / 未钉选看整池」作用域），原因 `account_egress`，
直到 Go 实现出口。

## 1. 三个对象

- **账号出口（per account）**：`account:egress:<ref>`。模式不变（pool / url / system / tun），pool 新增：
  - `scope`：全部节点（内置池，默认）/ 自建分组（复用订阅聚合的自建分组，可多选）/ 自选节点（多选）；
  - `strategy`：`shared`（共享轮换，现状）/ `sticky`（**账号独占节点**：同上游的账号尽量分到不同出口 IP，降低多账号同 IP 的风控风险；节点被拒时只在本账号范围内换）。
- **上游（per upstream）**：请求实际打到的接口（scheme + host），由系统从账号推导，用户不配：
  - OAuth / 官方地址账号 → provider 描述符声明的官方上游（claude 全部 OAuth 账号 = `api.anthropic.com` 一个上游）；
  - API Key + 自定义 baseUrl → baseUrl 的 host（每个中转是独立上游，默认无地区规则）。
- **上游地区策略（per upstream，共享）**：规则 + 拒绝特征 + 实测矩阵。同上游 N 个账号只有一份。

## 2. 节点能不能用：三层判定

`规则（用户显式 allow/deny） > 实测（节点 × 上游，带有效期） > 提示（预置，可被实测推翻） > 未知（允许，首次使用/测试时得出结论）`

- **节点的真实位置**：经节点查询出口 IP 归属（国家 / 省州 / 城市 / ASN / IP），缓存 1 天，不信节点名
  （实测：名为「剩余流量：50 GB」的节点出口在 US）。
- **规则维度**：国家、省州、城市、ASN、CIDR、单节点、自建分组；allow / deny。城市粒度有 IP 库误差，由实测兜底。
- **实测来源**：
  1. 被动探测（免费）：经节点无凭据请求上游。上游自身的 401/403 JSON = 可达；连接重置 / 超时 / 451 /
     命中拒绝特征 = 被拒；其它 = 可达未验证。（实测：HK01/HK02 → anthropic 连接重置/超时；US/JP/SG → 401。）
  2. 真实流量（最权威）：账号请求命中拒绝特征 → 立刻记「该节点 × 该上游 被拒」，并换下一个节点。
  3. 带凭据探测（可选，按上游开启）：用该上游任一账号打不计费只读接口（如 `/v1/models`），覆盖只在认证后才报地区错误的上游。
- **拒绝特征**：provider 描述符声明官方上游的地区拒绝形态（如 anthropic `Request not allowed`、
  openai `unsupported_country_region_territory`、gemini `User location is not supported`）；通用特征：451、TLS 阶段重置。
- **有效期**：「被拒」默认 7 天，全局值在 `aih server config set`（描述符表）+ WebUI 设置，可按上游覆盖；
  支持手动重置（单元格 / 单节点 / 整个上游 / 全部）；到期后台被动重测，通过即恢复。
- **规则变化**：上游开放新地区 → 重测通过自动恢复；上游新增限制 → 首个真实失败即生效并进事件流。
- **预置提示**：只给有明确官方政策的上游（anthropic / openai / google），标注来源与日期，UI 显示为「提示」。

## 3. 当前网络守卫（硬阻断）

账号的**有效出口**（绑定的 url / pool 节点 / system / tun / 未绑定时的直连或全局代理）落在该上游被拒的位置时：

- 网关：该账号不参与调度，返回 `egress_region_denied`（不记账号失败、不冷却，属配置问题）；
- CLI / 桌面端启动：拒绝启动，提示「当前网络（🇨🇳 上海 · AS4134）不被 api.anthropic.com 支持：请为账号设置出口，或开启本机代理 / TUN」，给出 `aih <cli> <id>` 对应的 WebUI 深链；
- WebUI：账号行显示红色「出口地区不可用」状态与「设置出口」按钮；
- 重新判定：启动前、每 5 分钟、网络接口变化时；结果缓存，避免每次请求查归属。

## 4. 交互（易用 > 稳定 > 美观）

- 出口设置弹窗（选 pool 后展开节点选择区）：范围（全部 / 分组 / 自选）、策略（共享 / 独占）、地区筛选芯片、
  节点表（国旗、真实出口城市 / ASN、延迟、对**本账号上游**的状态：可用 / 被拒（规则 · 实测 · 提示）/ 未知，附依据与时间）、
  「测试所选」、底部「将使用 N 个节点」。
- 保存后：「同上游（api.anthropic.com）还有 9 个账号未设置出口 —— 一键套用同样设置」（可勾选账号；
  独占策略下自动给每个账号分配不同节点），可忽略。
- 账号列表：出口徽标列 + 多选「批量设置出口」。
- 新页面「上游」：所有上游、各自账号数、规则、拒绝特征、节点 × 上游实测矩阵、全部重测、「从这次失败生成规则」。

## 5. 实现分期

| 期 | 内容 |
|---|---|
| P0 | Go Core 出口绕过：非直连出口的账号交还 Node（`account_egress`） |
| P1 | 上游推导 + 上游策略存储 + 节点真实位置 + 判定矩阵（含 TTL 配置 / 手动重置 / 到期重测）+ 被动探测 + 真实流量回写 |
| P2 | 池按「范围 × 策略」分监听端口（mihomo `listeners` 每个绑一组，已实测可行）；sticky 分配；轮换限定在范围内且跳过被拒节点 |
| P3 | 当前网络守卫（网关 / CLI / 桌面 / WebUI 四处） |
| P4 | 前端：节点选择区、同上游批量套用、账号列表徽标与批量设置、上游页面 |

## 6. 待做（已登记，未排期）：「加速器」式按客户端面选择出口

像游戏加速器选择要加速的游戏客户端：出口设置里多选作用面 —— 网关（relay）、CLI、桌面端、IDE 扩展（VS Code 类）。

- 现状：网关 / CLI / 桌面端已统一消费同一个账号出口绑定；IDE 扩展未覆盖；Go Core 未覆盖（见 P0）。
- 设计要点：绑定新增 `surfaces`（默认 = 该 provider 支持的全部面）；IDE 扩展需要按账号隔离的启动方式
  （独立 user-data-dir + `http.proxy` 设置或启动环境注入），需逐个客户端取证。
- 未绑定时的默认行为（第 0 节）在 UI 上明确显示为「跟随全局代理 / 继承系统环境」。

关键发现

服务器存在周期性事件循环阻塞

对最轻的 /healthz 做 40 次、间隔 150ms 的串行探测，仍反复出现卡顿：

stall  558 ms  t+1161      stall 1033 ms  t+4040
stall 1876 ms  t+~3900     stall  739 ms  t+4931
stall  734 ms  t+7926      stall  287 ms  t+9439

纯内存读的 /v0/webui/tasks 同样出现过 1840ms 单次延迟。这不是某个接口写得慢，而是进程内有同步阻塞，任何接口都可能被拖到秒级。

阻塞源：toolkit 在请求线程里同步起子进程

lib/cli/services/toolkit/proxy-target-plugins/proxy-command.js:5 的 execCommand() 使用 spawnSync，单次超时 4000ms。proxy 接口要为每个启用中的网络服务各调用 4 次 networksetup。

这些调用全部在 Node 主线程，阻塞期间所有 HTTP 请求（含 SSE 心跳、健康检查）一起排队。这解释了为什么 /healthz 会和 /toolkit/proxy 同时卡住。

测量口径告警

未做基准校准的探测产生过 3 次假阳性：app-install/jobs 881ms→0ms、studio/image/sessions 673ms→3ms、accounts 273ms→线上 p50 84ms。都是服务器卡顿所致，不是接口本身。

缓存冷热差异明显

projects 冷 447–847ms / 热 12–22ms；toolkit/apps 冷 3621ms / 热 7–17ms；lifecycle-capabilities 冷 1403ms / 热 1ms。命中缓存时都能进 300ms，问题在冷启动的同步扫描。

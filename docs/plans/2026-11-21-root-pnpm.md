# 根目录依赖迁 pnpm（2026-11-21）

## 结论

根目录 Node CLI 的依赖改用 pnpm，**hoisted 布局** + 全局 store：

- `.npmrc` 的 `node-linker=hoisted` 只在根目录生效；`web/.npmrc` 显式保持 `isolated`。
- store 在宿主全局（本机 `~/Library/pnpm/store`），同一依赖在所有 worktree 之间只占一份字节。
- 原生构建白名单：`node-pty`、`@lydell/node-pty`、`7zip-bin`（`pnpm.onlyBuiltDependencies`）。

## 实测

- 根 `node_modules`：npm 544M → pnpm 370M。
- 在一个只有 `package.json` + lock 的临时目录执行 `pnpm install --offline`：
  **370M 依赖只增加 3MB 真实磁盘、0.6s**（store 克隆/硬链接）。
- `node-pty` / `@lydell/node-pty` / `ssh2` / `undici` / `ws` / `yaml` / `7zip-bin` / `maxmind` / `werift` 均可加载；
  `aih --help`、`aih account list` 正常。

## 边界与注意事项

- 发行打包仍走 npm（`scripts/package/modules.js` 用 `npm ci/install`）；仓库的 lockfile 依旧被
  `.gitignore` 忽略，CI 会重新解析。
- 本地开发请统一用 `pnpm install`；`npm install` 会把 hoisted 树替换成 npm 布局（空间会回到各一份）。
- `pnpm install` 会触发根 `postinstall`（web 构建 + Go 构建）；并行会话有未提交 Go 代码时，
  Go 步骤可能失败但不影响依赖安装。

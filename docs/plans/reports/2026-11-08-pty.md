# pty-A：终端 PTY 迁 Go

基线：main @ 65555ab7（本 worktree 分支 slice/pty-wt）

## 结论

- 新增 `internal/runtime/terminalsession`：在现有 `internal/runtime/pty` 之上提供 create / attach / write / resize / kill + 输出回放缓冲，语义对齐 Node `lib/server/webui-terminal-routes.js`。
- 给 `pty` 的 Unix / Windows Session 增加 `Kill()`（不扩大 `Session` 接口，`terminalsession` 用可选接口探测），解决 `Close()` 只关 PTY 主端、不保证子进程退出的问题。
- 表驱动单元测试覆盖会话生命周期、尺寸变更、输出顺序、断线重连回放、并发写；另有真实 PTY 的创建 / resize / 写入 / 自然退出 / 退出后回放 / kill 测试。
- Node 侧未改动；HTTP 路由、SSE 分帧、tmux 持久化、mux 聚合尚未接线，见下文「接线方式」与「剩余缺口」。

## 先读代码得到的能力边界

| 现有 Go 能力 | 结论 |
| --- | --- |
| `internal/runtime/pty` | 已有 PTY 分配（`StartWithSize` / ConPTY）、`Resize`、`Read/Write`、`Wait`；没有回放缓冲、没有会话注册表、没有多订阅者、没有进程级 Kill（本次补了可选 `Kill()`）。 |
| `internal/runtime/multiplexer` | 只有 tmux 命令构造（`BuildLaunch` / `BuildAttach` / `List` / `Kill`）和 `Runner.Execute`；不持有会话状态，不采集/回放输出，`Execute` 只关心退出码。它是「如何调用 tmux」的适配器，不是终端传输层。 |
| `internal/runtime/persistent` | 管理 tmux 会话元数据（registry + manager），不碰 PTY 输出流。 |

因此：PTY 分配与 resize 可直接复用；回放、会话复用、订阅分发、生命周期需要新服务层补齐；tmux 持久化仍需要 Node 的 `webui-terminal-persistence` 那类「建 session / attach / 跨重启恢复」逻辑，Go 侧目前没有等价物。

## 服务接口

```go
service := terminalsession.NewService(pty.NewStarter(), terminalsession.Options{})

snapshot, err := service.Create(ctx, terminalsession.Spec{
    Key:  sessionKey,             // 对应 Node sessionKey，可空
    Path: "/bin/bash", Args: []string{"-l"},
    Env:  env, Dir: cwd,
    Size: pty.Size{Rows: 24, Cols: 80},
    Durable:    false,            // tmux 外层客户端时置 true
    Persistent: false,            // true 则空闲不回收
})

snapshot, err = service.Attach(ref)          // ref = termId 或 sessionKey
err = service.Write(ref, []byte("ls\r"))
snapshot, err = service.Resize(ref, pty.Size{Rows: 40, Cols: 120})
subscription, err := service.Subscribe(ref, 256) // 首帧是回放，之后实时帧
err = service.Kill(ref)
```

| 方法 | 语义 |
| --- | --- |
| `Create` | 启动 PTY；同 `Key` 的存活会话直接复用并返回 `Reused=true`；尺寸缺省 80x24，夹取到 2..500 列 / 1..200 行。 |
| `Attach` | 按 termId 或 sessionKey 查存活会话；已退出按 Node 语义返回 `ErrSessionNotFound`。 |
| `Write` | 按整次调用串行写入；并发写不会字节交错。 |
| `Resize` | 越界夹取；同尺寸跳过；底层失败时保留旧尺寸并返回错误。 |
| `Subscribe` | 先回放当前缓冲，再推实时输出与 exit 帧；慢订阅者被摘除，不能反压 PTY 读取。 |
| `Kill` | 结束进程、关闭全部订阅、移出会话表。 |
| `List` / `Reap` / `Shutdown` | 运维面：枚举、回收空闲/过期会话、关闭服务。 |

与 Node 对齐的默认值：最多 24 个会话、回放缓冲 256 KiB（按块淘汰最旧、至少保留一块）、空闲 30 分钟回收、退出后保留 30 秒供重连回放；`Persistent` 会话与仍有订阅者的会话不回收。

## 接线方式（Node 不改，供后续切片）

Node 现有函数到 Go 服务的映射：

| Node | Go |
| --- | --- |
| `openTerminalSession` | `Service.Create`（Key=sessionKey，Size={cols,rows}，Dir=cwd，Durable=是否 tmux 后端） |
| `handleTerminalAttach` | `Service.Attach`；需要重放时再 `Subscribe` |
| `handleTerminalInput` | `Service.Write` |
| `handleTerminalResize` | `Service.Resize` |
| `handleTerminalClose` | `Service.Kill` |
| `handleTerminalStream` / `handleTerminalMux` | `Service.Subscribe`；mux 需要额外的按 `muxId` 扇出层（本包按 session 订阅） |
| `createClientTerminalJobManager` | 不在本包范围；仍是 Node 的作业状态机 |

建议的落地顺序：

1. 在 Go HTTP 层新增 `/v0/webui/terminal/{open,attach,input,resize,close}` 与 `GET /stream` 的 handler，进程内单例 `terminalsession.Service`（`pty.NewStarter()`），鉴权继续走 Management Key。
2. 需要保留 Node 前端时，Node 只做反向代理/转发；SSE 帧格式（`connected` / `output` base64 / `exit`）和 16ms/64KB 输出批处理留在传输层，不要塞进 Service。
3. tmux 持久化：用 `multiplexer.BuildAttach` 生成 `tmux -u -L <socket> attach-session -t =web`，转成 `pty.Spec`（`Durable=true` / `Persistent=true`）；创建与 systemd scope 逻辑仍需从 Node `webui-terminal-persistence` 迁过来或继续由 Node 管。
4. 多 tab 单 SSE 的 mux 语义：在 Go 侧加 `muxId -> []termId` 的扇出，或在 Node 保留现有 mux 层。
5. 浏览器上传剪贴板图片、终端标题、`aih` shim / 登录 shell 选择、transport policy 仍建议留在 Node，直到有对应 Go 宿主能力。

## 剩余缺口与风险

1. **`go build ./...` 仍被基线问题挡住**：`nativeaccount.SanitizeClineProvidersDocument` 缺失，属于账号删除投影切片，不在 pty-A 范围；本分支未触碰。合并前需要对应切片补上该函数，或单独修基线。
2. **持久化没有真正迁走**：`Spec.Durable` 只影响回放清洗；`Persistent` 只影响回收。tmux 的建/attach/跨重启恢复仍在 Node。`multiplexer` 能拼命令，但 Go 侧没有「按 key 找 socket、attachOnly、systemd-run 脱离 cgroup」这一套。
3. **mux 未实现**：Node 一个面板一条 SSE 承载多 tab 的优化没有对应 Go 层；目前是每 session 一个订阅。
4. **输出批处理未实现**：Service 按 PTY 读块直接推帧；如果直接接浏览器 SSE，建议在 handler 上加 16ms/64KB batcher，避免小包风暴。
5. **终端作业语义未覆盖**：`client-terminal-job-manager` 的 queued/running/succeeded/failed、progress、30 分钟保留、同 `terminalId:action` 单活去重、SSE watchJob 都不在 Service 里；它和交互式会话是两套东西，不要混用。
6. **Node 侧的宿主细节仍未迁**：剪贴板图片、终端标题、transport policy、`aih` shim、`SHELL` 登录参数选择、cwd 回退 home（Service 已做 cwd 回退）、`TERM` 注入（Service 已做）。
7. **Windows 未真机验证**：`Kill()` 用 `command.Process.Kill()`，交叉编译通过，但 ConPTY 的进程树/退出码仍需真机确认。
8. **会话身份/鉴权**：Service 只按 ref 查会话，没有「termId 与 sessionKey 必须匹配」这类归属校验；接 HTTP 时要在 handler 层补，避免跨用户猜 termId。

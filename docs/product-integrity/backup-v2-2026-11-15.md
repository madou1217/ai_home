# G06 immutable backup repository v2 — 2026-11-15

Continues the original M0–M5 goal and the restore-preflight checkpoint `6c43a9000`. This package fixes the verified stable-path object overwrite failure; it does not mark G06's entire cross-platform matrix or the overall goal complete.

## Preserved contract and changed boundary

- Go scheduler/exporter and Node CLI now write an independent **v2 namespace**. `manifest.json` and `accounts/<provider>/<ref>.json` remain legacy read/migration sources; no v1 double-write, object deletion or GC.
- Raw complete native single-account documents are canonical JCS/RFC8785 plus LF, addressed by SHA-256 of the **uploaded bytes**. Go uses pinned `github.com/gowebpki/jcs v1.0.2`; Node uses ECMAScript primitive serialization and UTF-16 key ordering with explicit unsupported-value checks. A new raw-object digest is not the historical v1 record digest.
- Both writers verify existing immutable objects instead of overwriting them. Publication uses exclusive stage/CLOSE ACK then no-overwrite rename. Changed objects cannot mutate an old manifest's references. `--full` still transmits every current object through a fresh private stage and validates it, but never overwrites an existing digest object; upload statistics count newly published objects, not checks/reuse.
- A shared format contract defines 8 MiB object/manifest limits, 5000 manifest entries and 64 MiB active snapshot bytes. Parsers and writers use the same ceilings. Exceeding limits fails, never crops accounts/tombstones.
- Legacy import validates bytes/hash/provider/ref and preserves complete verified record content, including unknown top-level fields. Legacy tombstones whose objects are already absent retain explicit legacy evidence and are never restored as active objects.
- Skipped exports retain prior entries, report incomplete and do not update full-success time. Confirmed absent accounts become tombstones; reappearing accounts return active. No historical file is deleted.

## Publication protocol

Every cooperating v2 reader/writer uses a repository scope fixed to one SSH/SFTP generation. A complete random owner record is staged before the lock directory is published by no-overwrite rename. The scope never reconnects to continue an uncertain transaction.

```text
acquire complete writer lock
→ strict current/legacy manifest read
→ validate/create immutable account objects
→ validate full next manifest and references
→ publish immutable manifest snapshot
→ write and CLOSE owned publish intent
→ create/verify format marker
→ publish current manifest
→ atomically archive complete owner+intent directory to release lock
```

Reader scopes obtain a consistent manifest and bounded referenced objects before import. The lock also covers SFTP v3 recoverable replacement gaps; this is **cooperative serialization, not non-cooperative server CAS**.

Unknown transport/publication outcomes retain the lock and evidence. Confirmed publication with cleanup failure preserves `applied=true`; unknown does not invent a boolean. Normal completion archives coordination metadata instead of leaving an ownerless unlink/rmdir crash window. Metadata/old snapshots are not garbage-collected in this repair.

## Explicit recovery

```text
aih backup recover <id> --dry-run
aih backup recover <id> --confirm-stopped --owner <owner>
# A retained recovery attempt additionally requires its diagnostic tokens:
aih backup recover <id> --confirm-stopped --owner <owner> --recovery-token <token> --attempt-token <token>
```

- Default diagnosis and `--dry-run` are read-only, even when confirmation flags are also present. SSH connect does not create a missing target directory in this mode.
- The operator must actually stop the original writer and prior recovery processes. Tokens identify artifacts; they do not prove process death or cancel in-flight server operations.
- Recovery itself has a staged durable gate receipt and an atomic per-attempt claim. Concurrent recovery/resume attempts cannot both take the same old attempt. Gate stays until snapshot verification, publication, writer-scope release and final gate archival have completed.
- Old writer locks and auxiliary v3 replacement directories are quarantined by rename, not recursively deleted. Isolated owner/intent bytes are re-read and bound to the receipt digest.
- Desired snapshot and every referenced object are validated before publication. Current=desired confirms publication; current=previous allows completion. Missing current with nonempty previous requires matching preserved v3 previous-manifest digest. A divergent current fails closed.
- Verification failure retains both diagnostic cause and retry material. Once an operator repairs the missing/corrupt prerequisite and confirms old attempts are stopped, the same recovery can explicitly continue using its current tokens.

## Explicit remaining gates

- Real Windows SFTP server/PowerShell backup acceptance, WAN/large-account performance, disk-full/true power-loss durability, and long-run metadata growth remain unverified.
- Existing source exporters may already have decoded numeric credential fields through floating point before this layer. v2 rejects observed unsafe integers/nonfinite values/invalid Unicode; this does not retroactively prove upstream arbitrary-precision preservation. Unsupported input fails rather than silently coercing it.
- Shared server was not rebuilt/restarted/deployed. Source/temporary CLI acceptance is distinct from a running production scheduler applying this code. Recovery remains exposed through the existing Node backup CLI; Go is the core scheduled writer.
- Cooperative locks do not defend against malicious/non-cooperative remote writers, hard-link/path attacks by the backup host, or operators falsely confirming a live writer stopped. Hashes are integrity checks, not authenticated signatures; backups remain private plaintext credential documents over SSH.
- No automatic GC or cleanup of quarantines/completed receipts/old snapshots. Repository storage retention policy is a separate task.
- This establishes format/object/snapshot consistency within the verified local protocol matrix, not a transactionally consistent timestamp across every source account or rollback of partial account-import failures.

# Windows native scheduled-task restart — 2026-11-15

Scope: restore the existing restart capability during Node→Go migration without delegating to Node, elevating, or stopping another instance. Not a production rollout. Reviewed against the actual task/launcher marker generated by the legacy autostart path.

## Ownership and implementation

- Validate the instance's bounded marker/launcher/runtime-identity files, canonical same-home paths, current executable and process-start identity.
- Validate existing Task Scheduler action, principal/user/run level, enabled/demand-start state, and exactly one running instance.
- Bind ownership to the task's **EnginePID + InstanceGuid** and the daemon ancestry, not task label or equal launcher text. Recheck before lifecycle operations and after new process creation.
- Spawn a same-user noninteractive PowerShell worker outside the stopped task's job through local WMI. No RunAs, elevation, task registration or execution-policy bypass.
- Worker arms an instance file lock first. The host invokes its existing nonblocking graceful shutdown callback; neither management key nor credentials enter worker script/argv/environment.
- Wait for old daemon exit, finish only the validated old task instance if necessary, then run the same task. Succeeded requires new identity/PID/start ID, task instance ownership, and HTTP health after replacement.
- POST acceptance and `Pending` are nonterminal. Persisted worker status is authoritative across process replacement. Both WebUI and legacy management restart entrypoints share this adapter; status readback is available via the existing restart route with jobId.

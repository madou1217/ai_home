# Account browser shared stable host — stage 2A

The user approved continuing implementation of the ordinary stable browser-in-browser goal. This is the previously approved task-owned single-host prerequisite, not approval for a WebView, debugging bridge, extension installation, screen capture, input injection, or a per-account browser engine.

## Deliverable
A focused internal `accountbrowserhost` package starts at most one task-owned installed stable Microsoft Edge per dedicated SessionDir on macOS, without windows, pages, automation or debug flags. It verifies the application code signature and Microsoft stable bundle identity before launch. No browser is downloaded, installed, modified or adopted. The existing account-browser Host interface is intentionally NOT implemented: process survival does not prove frame/input/IME or account isolation.

## Lifecycle and safety
- A private locked file is held across the entire process lifecycle. A durable no-clobber active marker is published before spawn. Any leftover marker fails closed on a fresh supervisor, including after supervisor crash: never silently create a second host or kill/adopt recorded PIDs.
- Concurrent starts on one supervisor reuse its live process. Another supervisor/process gets busy. Cancellation before launch changes no running host; after spawn, ownership transfers to the supervisor independent of request cancellation. A cancelled initiating caller receives the actual current status/PID together with ctx.Err and must use explicit Shutdown; it must not assume that an error means no process exists. A cancelled waiter never terminates a shared host.
- Dedicated process group; signals require verified original root process start identity and group ownership, never process-name killing. Unexpected exit is failed, not an automatic restart. Shutdown retains the lock/marker if owned-group disappearance cannot be established. No PID file is treated as authorization to signal.
- Remember observed descendant birth identities, including later-detached children. Clear the active marker only following an empty original group and disappearance of all observed descendants; retain browser data and the reusable lock file. Never delete browser user data. No automatic stale recovery, browser process adoption, proxy/direct fallback or global mutation.
- Code signing verification uses Apple's codesign with an anchored Microsoft team/stable identifier requirement. Do not alter app xattrs to satisfy strict resource checks. This validates signed identity, not a promise that third-party sites never challenge users.

## Remaining gates
Full browser surface transport plus genuine user input/Chinese IME, persistent per-account browser profiles, OAuth, fail-closed account proxy, WebUI actions and desktop entry, real-site memory/latency acceptance remain unimplemented by this stage. An idle host is not the completed product.

## macOS observation limit
Darwin process groups are not kernel-enforced process-tree containment. A descendant that forks and detaches entirely between snapshots can be unobservable. The implementation checks known birth identities and the original group and fails closed on scan/ownership uncertainty, but cannot claim guaranteed containment of all possible descendants. No unattended service integration or automatic restart is provided; a stronger kernel/job-based lifecycle prerequisite remains necessary before broader host adoption.

## Conservative I/O failure policy
An active-marker write/sync failure before spawn leaves a dirty marker and launches no browser; explicit recovery may be required even though no browser was started. Marker removal/sync uncertainty retains the lock for retry. Handle-close errors are reported but are not a guarantee that the OS lock remains held. PID records never authorize cleanup.

# Interactive ordinary browser surface — first usable slice

Approved user goal: actually browse websites inside WebUI, not further foundation-only deliveries. Keep installed signed stable Edge, no Electron/WebView/CDP/headless/automation flags, no profile mixing or third-party policy promises.

## Concrete design
A single task-private stable Edge host creates an ordinary about:blank window only after the authenticated user's explicit Start action. A dedicated Swift helper uses ScreenCaptureKit SCStream with a desktopIndependentWindow filter to stream JPEG frames (bounded, latest only). CoreGraphics per-PID events forward user clicks, scrolls, keys and committed text; no AppleScript/AppleEvents, accessibility scripts, global event taps/posting, clipboard, page scripts, credential reads or arbitrary PID/window selection from HTTP.

A native preflight in the actual helper process checks capture/event access without prompting. Permission missing => explicit unavailable, no permission mutation or whole-screen fallback. Each event revalidates owned PID birth identity and the exact task window. Single controller, single task window; no account-browser Host registration or multi-account cookie/proxy claims. Account-profile foundation remains separate. Native capture/input is supported only on macOS14+ with installed stable Edge and toolchain/helper. Unsupported platforms report it.

## Focus boundary discovered in real diagnostics
The task-only postToPid Cmd+N probe created a real Edge window but changed foreground application. It was stopped and task roots exited; no personal windows were captured. Therefore the UI MUST state before Start that task Edge may become foreground. Product control requires the user's deliberate click; agent must not repeat focus-changing input or capture without explicit user acceptance. Unicode commits are not a promise of native background IME. The view forwards browser-side composition commits; IME, popup focus and multi-window must be verified, never assumed.

## Validation gate
Build/vet native/runtime/transport and frontend; use actual native helper preflight without prompting. No tests. Real capture/input and final WebUI visual acceptance require explicit user consent to possible foreground change after the observed diagnostic. Build is not browsing acceptance. No production restart/deploy or permission/extension install. Scoped explicit-path reviewed commit/push with peer index unchanged. Genuine public-site navigation, click/scroll, Chinese committed text, reconnection/persistent website cookies/proxies remain pending until performed.

## Review corrections and current proof boundary
Native output is a single latest-frame slot plus <=8 control events on a separate writer queue; capture holds at most one main publication and timestamps it at acquisition/confirmed idle, not eventual write time. Capture termination and input submission share a synchronous terminal gate; queued input cannot begin after stop. Input includes last-drawn frame sequence and expires after2.5seconds. Input rate is <=90commands/second with <=8 pending native operations. Invalid/resize/multiple-window events fail closed. Shared run may be nonprivate; owned child roots and inode pairs are validated. Service retains failed-cleanup host for internal RetryCleanup and returns cleanup failure.

After explicit Start the single WS receive pump remains active throughout compilation/preflight/host creation; disconnect/close cancels preparation before it can silently continue. Actual loopback HTTP/WS checks pass without opening a browser: bearer401/200, cross-origin403, invalid credential1008, valid waiting-for-start, clientPID JSON refusal, start-immediate-disconnect cancellation before browser data, race detector clean. Native compile plus actual helper preflight and Go build/vet pass. TypeScript check and Node22 Umi build pass; default Node26 build fails in installed dependency http_parser, not concealed by changing dependencies.

Still NOT observed: first captured browser frame, click/scroll effect, text/IME composition, actual website navigation, popup routing, reconnection/login cookies, per-account isolation/proxy. This source is awaiting user-start acceptance, not a proven usable browser release. No production restart/deploy.

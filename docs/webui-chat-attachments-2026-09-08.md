# WebUI 文本附件与统计条修复

## 原因与行为

旧版 MessageArea 的文件选择、拖放和粘贴入口仅接收图片，Markdown 因此被静默忽略。批量读取的多个 FileReader 回调复用旧 images 数组，导致附件相互覆盖。统计条没有输入框使用的最大宽度约束，在宽屏下横向撑满父容器。

本次让两套聊天输入入口共用附件格式和读取规则，支持 Markdown、UTF-8 文本、常见代码、JSON/CSV 等文本数据文件，以及原有图片格式。附件批次串行合并；文档可以单独发送，并保留到排队、草稿编辑、历史和后续追问。纯聊天向模型传递文档正文，原生工作会话提供本地文档路径；Codex 的 localImage 输入只包含图片。文档写入既有附件目录，使用安全文件名和 0600 权限。

限制：每次最多 8 个附件、总计 20 MB；图片单个 10 MB，文本单个 1 MB。PDF、Office 和其他二进制格式不在本次支持范围内。统计条与输入框共用最大 840px 宽度，窄屏允许内部统计文字裁剪，避免撑宽页面。

## 设计审查

| 文件/模块 | 模式 | 原因 | 验证证据 |
| --- | --- | --- | --- |
| contracts/chat-attachments.json、attachment-files.ts | 共享策略 | 统一附件格式、限额与文件读取规则，避免两套输入入口继续分叉 | Web 测试、ESLint、构建及批量上传实测 |
| use-chat-file-input.ts、use-composer-attachments.ts | 串行任务队列 | 合并异步文件读取结果，避免多批次相互覆盖 | 同时拖入两份 Markdown 并追加 JSON 的真实页面验收 |
| chat-document-attachments.js、codex-session-driver.js | 适配器 | 在发送边界将文档转换为正文或路径，保持图片协议语义 | 后端测试、Codex driver 测试、真实纯聊天回答 |

SOLID：读取、持久化与 provider 输入转换分别由独立模块负责。DRY：复用附件契约、读取器和既有存储路径策略。KISS/YAGNI：采用现有消息正文和本地文件通道，不增加二进制解析依赖或新的附件存储系统。统计条仅调整 CSS 约束，无需额外设计模式。
